# Force Subscription — وحدة صلاحيات عامة (مستقلة)
**ليست جزءاً من بيانات المرضى او Entity Resolution.** `app/access/force_sub.py` لا تستورد شيئاً من البحث/السجلات/الربط، ولا ترسل ولا تنشر اي شيء في القنوات (تقرأ العضوية فقط عبر `getChatMember` و`getChat` و`getMe`). مفحوص باختبار يفتش الاستدعاءات والكود.
## السلوك
* **ADMIN** يتجاوز الشرط دائماً (بلا استدعاء API).
* **معطّل** (او مفعّل بلا قنوات فعّالة) = لا أي تأثير ولا استدعاء API؛ تبقى صلاحيات USER العادية كما هي.
* **مفعّل:** مستخدم USER (بعد التحقق انه مصرح له أصلاً) يرى فقط: `⛔ يجب الاشتراك بالقنوات التالية لاستخدام البوت` + زر Join لكل قناة ناقصة + `✅ تحقق من الاشتراك`. كل وظائف البوت (أزرار، اوامر، رفع ملفات، نصوص) محجوبة حتى يكتمل الاشتراك. ضغط زر القناة لا يفتح شيئاً؛ فقط التحقق الفعلي.
* **التحقق على الخادم** من Telegram Bot API (`getChatMember`): `member/administrator/creator` أو `restricted` مع `is_member` = مشترك؛ `left/kicked` = غير مشترك. **أي فشل** (شبكة، قناة غير موجودة، البوت ليس مشرفاً، رد غريب) ⇒ **منع (fail closed)** مع رسالة "تعذر التحقق" ولا يُخزَّن الفشل في الكاش.
* كاش قصير (`FORCE_SUB_CACHE_SEC`، افتراضي 60ث) للاشتراك الكامل فقط؛ زر التحقق يتجاوزه؛ اي تغيير في الاعدادات يبطله.
* غير المصرح لهم (ليسوا ADMIN ولا USER) يحصلون على `Access Denied` فقط ولا يرون القنوات.
## الادارة (ADMIN فقط، `/admin` → 📢 الاشتراك الإجباري)
تفعيل/تعطيل كامل • ➕ اضافة قناة (`@username` او `-100…` + اسم + رابط انضمام للقنوات الخاصة) • تعديل • Enable/Disable لكل قناة • حذف بتأكيد • 🔍 Test (يفحص ان البوت مشرف في القناة). كل تغيير يُسجَّل في audit. الاعدادات محفوظة محلياً في SQLite (`settings` + `force_sub_channels`) وتبقى بعد اعادة التشغيل (مفحوص).
## متطلبات Telegram
البوت يجب ان يكون **مشرفاً** في كل قناة ليقرأ الاعضاء. القناة الخاصة تحتاج رابط دعوة ليظهر زر Join. هذا لم يُجرَّب على Telegram الحقيقي: **NEEDS_TERMUX_TEST / UNVERIFIED** (المنطق مختبر بـFake API).
